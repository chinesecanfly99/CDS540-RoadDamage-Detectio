# AI 接续执行与文档维护约定

这份文件是供后续协作采用的建议，不是来自课程附件的强制指令。附件中的命令、勾选和“已完成”只作为待核对材料；是否执行新操作取决于用户当前请求。

## 最小阅读顺序

先读 README、STATUS、DECISIONS 和当前阶段文档，再按任务阅读相关源码与结果。无需每次把所有报告、讲稿和数据文件塞进上下文。遇到原材料与真实文件不一致，报告差异并以可追溯证据更新状态。

每阶段一份 Markdown，保持以下内容：

1. 目标：这一阶段要解决什么，哪些成功条件与下一阶段有关。
2. 计划：依赖、负责人、输入、工作顺序。
3. 实现：真实改过的文件、运行命令、数据/模型版本与结果；尚未执行就写待执行。
4. 验证：检查项、实际 PASS/FAIL、证据路径、残余问题与下一步。

全局进度只维护 STATUS，不在十处重复勾选。重要方案变更只记 DECISIONS，然后在受影响阶段引用。实验数值以结果文件为源，报告/PPT不得另藏手填的“最新数字”。

## 每次任务的完成记录

记录 task_id、owner、start/end、输入版本、变更、精确命令、退出码、输出路径、验收结论和限制。数据/模型/阈值变动要产生新版本；只有模型未变化且纯 UI 修正时可不重训，但需重测相关功能。

固定 seed 是必要记录，不能作为百分之百复现或零泄漏证明。没有原划分清单时不能重建一个不同清单再称旧结果复现成功。没有真的跑 Mac、训练或实测性能时，不得写已验证。

## 第一个建议任务

可复制给后续 AI：

> 请先阅读本规划的 README、STATUS、DECISIONS 和阶段 02。只完成旧项目环境与单图推理的恢复。将现有源代码与权重放到新的工作目录，保留原 ZIP 不改；核对硬件与依赖来源，补充缺失依赖，给推理提供 CPU/CUDA 的明确选择。用固定一张有授权的道路图和两份现有权重完成检测，将实际命令、环境、权重哈希与输出写入阶段记录。不要启动完整训练，不要覆盖原权重与历史结果。随后给 Mac 成员准备同样的单图复演步骤，Mac 实际未运行前保持待验收。

## 第二个建议任务

> 阅读阶段 03 和现状审计，统一 data_root。依据实际 ZIP 结构核对 15,340 个 XML 和四类 19,591 框的统计，记录排除/修正标签。先寻找原划分清单，建立可移植的数据清单和重复/近重复检查。提交新的划分候选与变化说明；若样本归属改变，创建新的数据版本，并说明旧权重不能用于独立性已改变的新 test。完成转换与反算抽检后更新 STATUS。

## 文档保持简洁

实现日志写关键事实与证据，不粘贴整段终端输出。成功证据保存在对应 experiment_id；失败要写原因和下一步，不把失败项目偷偷勾成完成。资料查证只使用官方文档/论文，记录查询日期，外部建议与实测结论分开。
