# Windows 与 Mac 的部署和演示验收

> 当前安排：用户于 2026-10-16 明确跨电脑先不验证，以下矩阵保留为后续验收计划。本轮仅完成本机检查。

## 推荐选择

组内选定一台适合训练的电脑集中运行实验，其他成员在各自目标环境独立运行同一个 Gradio 应用。设备分配与成员职责分别讨论。默认支持 CPU，NVIDIA CUDA 与 Apple MPS 是经过检测和验证后启用的加速项。Linux、Docker 和嵌入式设备不列入本次必须学会或必须部署的内容。

先做图片交互，再做短视频离线处理，以便先建立稳定的演示链路；不需要把整套训练数据发给每位组员。

| 方案 | 是否推荐 | 能证明的事情 | 局限 |
| --- | --- | --- | --- |
| Windows 本机应用 | 必做 | 训练机/展示机独立运行 | 仍须验证另一台新环境 |
| Mac 本机应用 | 必做 | macOS 实际模型推理与输出 | 芯片/系统/依赖需真机记录 |
| Mac 浏览器访问 Windows 局域网服务 | 备用 | 网络访问和课堂多终端展示 | 推理仍在 Windows，不能代替 Mac 独立运行 |
| 托管网页，如 Gradio Spaces | 可选 | 外部人员凭链接操作 | 账户、费用、资源、冷启动、网络访问需现场验证 |
| 云 GPU 训练 | 按预算需要 | 加快训练或提高显存容量 | 与网页托管、跨平台本地兼容是不同事项 |

云端不必优先。Hugging Face 的[当前 Spaces 说明](https://huggingface.co/docs/hub/spaces-overview)区分硬件费用和创建计算型 Space 的账户要求，不能承诺免费账户就能创建可运行 Gradio 的服务。需要远程链接时，再核对实际账户资格与费用；不要只凭教程中的“免费”作决定。

## 同一发布包应包含

Python 源码、经验证的依赖与安装指引、两平台启动文件、选定演示权重、模型卡/哈希、类别及阈值配置、固定样例、输出样例、故障排查说明。原始训练数据单独存放，不要求每位成员下载；依赖和权重首次联网准备好后，课堂演示应能离线运行。

后续启动文件建议为 `launch_windows.ps1`、`launch_macos.command`。首次安装和日常启动分开；启动时显示实际 device 与模型版本，缓存模型避免每次上传重载。不在每次启动时自动升级依赖或训练模型。

## 核心功能

上传图片后显示原图、叠框图、四类数量、置信度、复核级别及触发原因，支持导出 JSON/CSV 与图片。无目标类检出时清楚说明当前阈值下未检出，不宣布道路安全。

短视频支持处理进度与下载。上限按实测设备设定，例如先以 10–20 秒作为展示样例；超限要提示或明确标注截取范围，不能静默只处理 120 帧。保留源视频 FPS、尺寸与实际处理时长；浏览器播放编码须在 Windows/Mac 两边验证。

规则层将“Urgent repair crew dispatch (24–48h)”等无依据时限改为“建议优先人工核查”，展示触发类别和规则版本。无检测状态使用 `NO_TARGET_DETECTED`；低质量/模糊可提示 `REVIEW_REQUIRED`。不要把置信度当作概率已校准或真实损坏等级。

## 验收矩阵

所有条目初始为未执行。由实际操作者记录机器、环境、模型哈希、命令、输出路径、时间及 PASS/FAIL，不用截图代替所有证据。

| 编号 | 操作 | Windows | Mac | 通过条件 |
| --- | --- | --- | --- | --- |
| A01 | 干净虚拟环境按说明安装 | 待测 | 待测 | 无私有开发路径/未说明额外依赖 |
| A02 | 使用固定一张图加载模型 | 待测 | 待测 | 模型/四类正常，不误用 COCO 权重 |
| A03 | 关闭 CUDA 以 CPU 启动 | 待测 | 待测 | 无 CUDA 调用报错，输出有效 |
| A04 | 验证本机加速 | CUDA 待测 | MPS 可选 | 可用时成功；不可用明确切换，不伪报 GPU |
| A05 | 固定样例集的检测与导出 | 待测 | 待测 | 图、类别、坐标定义一致；无损坏文件 |
| A06 | 无目标、暗图、模糊、困难样例 | 待测 | 待测 | 状态文字准确，不输出无依据安全保证 |
| A07 | 非图片、损坏文件、超限输入 | 待测 | 待测 | 友好错误提示，应用继续可用 |
| A08 | 连续处理 20 次及切换样例 | 待测 | 待测 | 无串图、结果残留、明显持续内存增长 |
| A09 | 真实短视频处理并浏览器播放 | 待测 | 待测 | 帧数/时长明确，输出可播放，耗时实测 |
| A10 | 预装完成后断网启动 | 待测 | 待测 | 不再下载模型/字体，固定样例完整运行 |
| A11 | 包含中文和空格的目录启动 | 待测 | 待测 | 路径解析与导出正常 |
| A12 | 与参考输出比较 | 待测 | 待测 | 数值差异在预先约定范围，临界阈值差异列明 |

跨设备浮点误差可能使阈值附近框数量不同，不要求逐字节相同。预先建立固定样例、同 conf/iou/imgsz/精度与可解释容差；若使用静态 ONNX，统一 letterbox 与 NMS 策略并做整个测试集精度回归。不能用“ONNX 导出成功”代替推理一致性与精度验收。参考 [Ultralytics 导出说明](https://docs.ultralytics.com/modes/export/)。

## 课堂保障

优先展示本机图片交互、一个困难案例及一段真实短视频。提前准备处理前/处理后录屏和结果导出作备份；录屏要明确标为预录。演示时说清是在本机运行还是访问另一台服务，不把网络浏览器访问包装成另一平台模型部署。

若采用远程服务，使用同一冻结模型和配置，不把全量数据上传到网页项目中；先从教室实际网络和无登录浏览器验证访问、冷启动与下载。公网发布是可选工作，本次规划没有创建服务器、购买服务或上传文件。
