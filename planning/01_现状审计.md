## 优先修正的问题

| 编号 | 发现及依据 | 影响与处理 |
| --- | --- | --- |
| P01 | `requirements.txt` 漏 `ultralytics`；报告生成还用 `reportlab`、`pypdf`、`python-pptx` | 新电脑安装清单后仍缺库。分离训练、演示、文档依赖并验证 |
| P02 | CUDA 构建的 torch/torchvision 被直接锁进共享清单，且环境来源不足 | 不能直接当成 Mac 安装方案；官方配对、安装渠道和本机驱动需验证 |
| P03 | ZIP 中没有 `data/manifests`、`env_check.txt`、训练 runs 或根 README | 有模型和结果仍无法恢复准确划分/命令。先找回原文件，不能用相同 seed 冒充相同划分 |
| P04 | `parse_and_check_annotations.py` 使用 `DGS2022数据/国家/国家/train`，实际 ZIP 展开只有一层国家目录 | 当前数据按普通解压不能直接接上所有脚本。统一 `data_root` 配置与清单 |
| P05 | 原划分只核对图片路径互斥，并按“任意对象阳性”分层 | 没有证明相邻帧、近重复图无泄漏，也不保证四类分布一致。新增 group_id 与目标类统计 |
| P06 | 原 n 训练上限 50、patience 12；s 为 25、patience 10 | 报告不能笼统称完全相同训练协议。新比较统一预算并记录实际停止轮次 |
| P07 | `evaluate_baseline.py` 固定从未打包的 `runs\detect\runs\baseline_n\...` 复制权重 | 即使现有 `models/baseline_best.pt` 在，也会先失败。将评估与权重复制解耦 |
| P08 | 多个评估/计时脚本固定 `device=0`，并无条件调用 CUDA API | Mac/CPU 无法直接运行全流程。推理、评估、计时都要显式设备分支 |
| P09 | `evaluate_domain_shift.py` 将旧域内指标写死；转换器生成的域配置只有 test，但评估读取 val，包内 YAML 又将 train/val/test 都指同一目录 | 重新生成配置后可能与现有评估不兼容。显式使用 test，禁止把美国目录传给训练 |
| P10 | `benchmark_runtime.py` 以 CUDA Event 包住整个 `model.predict`，图片事先加载，未测解码/写盘/网络 | 不能叫纯 forward，也不能叫上传到视频输出的完整 E2E；分开测量并正确命名 |
| P11 | 不同报告/CSV 给出约 61/33.7、45.5/38.6、140–190 FPS，文字还出现 s 超过 100 FPS | 测量边界可能不同且文字有冲突。统一测试协议后重新生成全部材料 |
| P12 | 将笔记本 RTX 5070 数据推广到 Jetson/树莓派，且称 P95 保证零丢帧 | 无实测不能证明目标设备可用；P95 也不是最坏延迟。删除保证式结论 |
| P13 | `demo.py` 默认将目录前 120 张图按 15 FPS 合成，HUD 写死 RTX 5070 | 这是约 8 秒图片序列演示，不能作为真实连续行车视频/实时处理证据。补真实视频并动态读取设备 |
| P14 | `generate_failure_analysis.py` 挑前若干图片后直接写 FP/FN 标题，没有 GT 匹配 | 图名不能证明是误检/漏检。先按类别与 IoU 匹配，再人工检查案例 |
| P15 | 无检测输出被写成 Pavement sound，优先级附具体 24–48h 派修话术 | 未检出并不等于安全，数据也无深度/严重性/修复时限真值。改为人工复核提示 |
| P16 | 老任务总览与细项勾选不一致，reports/submission 有重复 PDF/PPT | 使用一份 STATUS 和一个最终发布目录，报告由结果统一生成 |

这些是证据与工程问题，不意味着已有工作无效，也不能仅凭它们断言结果伪造。复核通过的部分继续复用；受数据/协议变化影响的结果重新计算。

## 对你原思路的修正

**“选题第一步已经完成”只完成了一部分。** 还要把使用者、输入输出、四类边界、人工复核定位、模型选择准则和验收门槛写清楚。

**“每一步加计划/实现/目标/验证文档”方向可行，但文件越多不等于越清楚。** 每阶段一份文件，进度只维护一个入口；实现部分记录真实变更，验证部分附结果路径和失败项。

**“最后再考虑部署”需要调整。** Windows/Mac 的最小推理要在第一周通过，最终阶段才做完整验收。

**“云端服务器跑最好”缺少判断条件。** 先在已有 NVIDIA 电脑做短测；只有显存或总训练时长影响排期时才用云 GPU。云训练和远程网页演示是两件事，不能混成一个需求。

**“能跑在苹果上”还要具体化。** 至少一台真实 Mac 独立加载模型完成输入输出；Mac 浏览器访问 Windows 服务，只证明远程访问，不能当作 Mac 本机推理通过。
