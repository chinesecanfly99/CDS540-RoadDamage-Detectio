## 4 新电脑上的环境检查

建议先创建独立虚拟环境。Python 3.11 可作为待验证候选，最终以目标系统、芯片和所选库版本的可安装性为准。不要把现有全量 `requirements.txt` 无检查地安装进日常环境。

| 部分 | 用到的库 | 安装策略 |
| --- | --- | --- |
| 最小检测 | torch、torchvision、ultralytics；图像读写相关依赖 | 先选择官方匹配的 PyTorch 组合，再装适配的 Ultralytics 并核对实际解析版本 |
| 现有规则与视频 Demo | numpy、opencv-python、pandas 等源码实际导入库 | 即使只调用部分功能，也要检查模块顶层 import；可随后拆分纯规则依赖 |
| 数据与评估 | pandas、numpy、Pillow、PyYAML、matplotlib 等 | 按实际调用入口补全并锁定 |
| 报告生成 | reportlab、pypdf、python-pptx | 只生成报告/PPT时需要，单图检测不用先装 |
| 新网页界面 | 规划采用 Gradio | 原包尚未实现；不是验证原项目最小运行的前置条件 |

Windows 有兼容 NVIDIA 环境时可在 CPU 测通后启用 CUDA；无可用 GPU 仍应能做 CPU 推理。macOS 不安装 CUDA wheel；CPU 先通，MPS 加速按实际芯片、系统和依赖检测。不要将 `device=0` 解释成所有电脑都有的通用设备。

原清单的 CUDA 构建版本只作历史记录，torch/torchvision 组合、安装源与驱动兼容性尚未验证。没有证据表明应安装本地完整 CUDA Toolkit 才能做这次推理；按官方 PyTorch 安装方式选择发行包，遇到具体兼容错误再处理。无需为迁移演示重装系统或先学 Docker。

## 6 第一件要做的事 CPU 单图推理

这是一个可由对方 AI 新建的最小测试入口示例，**不是原项目已有文件，也尚未执行模型测试**。先准备一张普通道路 JPG：优先从原始数据取图，不要把已经画好标注框的报告示例当作原图。保存为任意实际路径。

将以下示例另存为 `smoke_infer.py`。使用绝对输入路径，可以在任意工作目录调用。输出目录须是本次新目录。

```python
import json
import sys
from pathlib import Path
from ultralytics import YOLO

if len(sys.argv) != 4:
    raise SystemExit("Usage: python smoke_infer.py MODEL_PT INPUT_IMAGE NEW_OUTPUT_DIR")

weights, image, output = [Path(x).expanduser().resolve() for x in sys.argv[1:]]
if not weights.is_file():
    raise FileNotFoundError(f"Missing weights: {weights}")
if not image.is_file():
    raise FileNotFoundError(f"Missing input: {image}")
if output.exists():
    raise FileExistsError(f"Choose a new output directory: {output}")

model = YOLO(str(weights))
expected = {0: "D00", 1: "D10", 2: "D20", 3: "D40"}
actual = {int(k): str(v) for k, v in model.names.items()}
if actual != expected:
    raise RuntimeError(f"Verify the class mapping before proceeding: {actual}")

result = model.predict(
    source=str(image), device="cpu", imgsz=640,
    conf=0.25, iou=0.7, save=False, verbose=False
)[0]

records = []
if result.boxes is not None:
    for box in result.boxes:
        cls = int(box.cls.item())
        records.append({
            "class_id": cls,
            "class_name": actual[cls],
            "confidence": float(box.conf.item()),
            "xyxy": box.xyxy[0].cpu().tolist(),
        })

output.mkdir(parents=True, exist_ok=False)
result.save(filename=str(output / "prediction.jpg"))
report = {
    "model": str(weights), "input": str(image), "device": "cpu",
    "imgsz": 640, "conf": 0.25, "iou": 0.7,
    "class_mapping": actual, "detections": records,
    "note": "No detections does not establish that a road is undamaged."
}
(output / "prediction.json").write_text(
    json.dumps(report, ensure_ascii=False, indent=2), encoding="utf-8"
)
print(f"Completed CPU inference. Detection count: {len(records)}. Output: {output}")
```

调用形式：

```text
python smoke_infer.py "现有权重的实际路径.pt" "原始道路图的实际路径.jpg" "本次新建输出目录"
```

上面的中文路径是填写说明，不是要原样执行的文件名。对方 AI 应替换为机器上的真实路径，并记录准确命令。先用 n 权重跑通，再使用 s 权重复演；加速设备在 CPU 成功后单独验证。

运行完成后检查：类别映射正确，图片能打开，JSON 可解析且坐标在原图范围内；允许某张图片零检出。至少换一张含清楚目标的图片继续观察，不能用“必须有框”作为所有输入的程序成功标准。

## 7 单图通过后再恢复其余链路

### A 规则与媒体演示

复用 `scripts/priority.py`，但导入其类不等于执行它的 `__main__` 测试入口；后者还要求 `data/manifests/test.csv`。最小演示可直接把单图推理结果传给规则，无需先准备全部清单。

将 `demo/demo.py` 改成可指定真实输入/输出与设备的入口。先处理少量同尺寸图片，再处理短视频。检查 `cv2.imread`、VideoCapture 与 VideoWriter 是否成功；遇到不同尺寸帧时统一适配并说明，不能静默产生损坏视频。验证实际保存文件、帧数和两种浏览器中的可播放性。将“Pavement sound”改为“当前阈值下未检出目标”，规则仅作人工复核辅助。

### B 数据与评估

按实际目录展开三国数据，依次恢复：库存清单 → XML 检查 → 精确划分清单 → YOLO 标签/目录 → 本机数据 YAML → 指定权重评估。原始有标注数据共 15,340 张；另外 3,868 张官方 test 无公开 XML，只能定性展示，不能本地计算 mAP。

恢复原划分时按相对路径/样本 ID 重定位，并核对图像内容哈希，不能对旧绝对路径简单全局替换后就宣称相同数据。新划分改变训练/验证/测试归属时，旧权重的独立性不再得到保证，后续正式指标使用新版本训练和评估。运行评估时记录 class mapping、支持样本数、conf/iou、imgsz、设备与指标口径。

### C 训练可行性

只有需要重新训练或恢复完整训练链路时，才准备初始化预训练权重及训练集。`yolo11n.pt`、`yolo11s.pt` 是初始化模型名称，和包内已训练好的 `baseline_best.pt`、`compare_yolo11s_best.pt` 不同；不保证原包已含初始化文件。需要联网获取时记录来源，离线环境则预先准备。

先检查原 `scripts/train_yolo.py --help`；代码已有 model/data/epochs/batch/device/workers/seed 等参数，但其他训练/评估入口不一定具备相同参数，不能凭空给它们追加命令选项。

对固定小样本做 1–3 epoch 试跑，明确记录这是 smoke test。CUDA 可用时用小 batch 起步，内存不足先减 batch；CPU 也可以验证程序，但不预先承诺完整训练速度。正式训练另建 experiment_id，不覆盖 smoke 或历史 runs；同协议比较后再开展长时间运行。


| 验收项 | 状态怎么写 |
| --- | --- |
| 模型文件和类别核对 | PASS/FAIL，并附权重哈希 |
| CPU 单图推理 | PASS/FAIL，并附输出与准确命令 |
| 当前设备加速 | PASS/FAIL/NOT_TESTED，不能因 CPU 成功就默认 GPU 成功 |
| 规则与短视频处理 | PASS/FAIL/NOT_TESTED，附实际输入输出 |
| 数据与旧划分恢复 | 已恢复/新建版本/缺失，分别说明 |
| 评估与训练 | 实际执行结果或 NOT_TESTED，不将其混同于单图通过 |
| 其他电脑 | 仅记录该电脑实际运行的结论，不能从一台机器推广 |

第一次交接的最低完成标准是：**在当前电脑确实加载两份既有权重，并各完成单图输入到结果导出，给出真实输出和可复演步骤。** 其余链路逐步扩展，有缺失就准确列出，不用一句“整个项目已跑通”概括不同完成程度。
