# 数据协议 实验矩阵与评估指标

## 数据协议先于训练

沿用主叙事：捷克与印度作为源域，美国有标注的官方 train 作为国家留出评估域。三国官方无标注 test 只能做定性展示，不能计算本地 mAP。

源域约 70/15/15 划为 train/val/test。先按可获得的采集序列、道路路段或近重复组生成 `group_id`，再划分；国家、四类多标签与是否含目标尽量平衡，精确比例可为避免拆组略作偏离。不得为了维持旧的 7,375/1,581/1,579 数字强行拆开相关样本。没有真实序列信息时，明确记录近重复分组启发式与残余泄漏风险；不能直接把相邻文件名视作同一路段的确证。

记录每图 `image_id, relative_path, country, source_split, group_id, sha256, width, height, target_class_counts, has_target, assigned_split`。数据版本还包含类别映射、被排除标签、转换代码版本、划分 seed 和清单哈希。相同 seed 但清单顺序/分组算法变化，并不产生相同划分。

原始 20,962 框与四类 19,591 框分开统计，1,371 个非目标框只排除不随意合并；笔误 D0w0 到 D00 记录为显式修正。缺 XML 或解析失败要停止并列错误，不得像旧转换器一样静默生成背景标签。仅当确认没有目标类标注时才生成空标签。

美国的既有结果已经被查看。它仍可作为未参与权重训练的域外评估，但不能再称“从未被查看的盲测”。不得根据美国结果反复调参再用同一美国数据宣称独立确认；如做目标域微调，建立独立 adaptation/dev/test 分组，并改变实验名称与结论。若补充全新外部图像作为未见评估，也要说明来源与样本量，不能替代标准对比。

## 实验矩阵

| ID | 配置 | 用途 | 是否必做 |
| --- | --- | --- | --- |
| R00 | 现有两份 PT + 原清单恢复 | 核实旧结果，保留历史证据 | 优先；清单缺失时明确不可精确复现 |
| B01 | YOLO11n，冻结数据 v1，640 输入 | 新协议轻量基线 | 数据归属改变时必做 |
| B02 | YOLO11s，其他协议同 B01 | 比较模型规模的质量/速度代价 | 必做 |
| I01 | B02 同模型，增加一项有依据的训练增强 | 检验针对性改进 | 推荐主改进 |
| T01 | 冻结权重，在源域 val 扫置信度 | 提高 D40 复核召回并约束误报 | 必做，无需重训 |
| G01 | 冻结选择后评估美国四类 | 国家域外泛化 | 必做 |
| S01 | 固定测试子集 clean/低光/模糊/噪声 | 受控扰动敏感性 | 必做，可减到两种扰动 |
| P01 | Windows CUDA/CPU、Mac CPU/可选 MPS | 部署运行适用性 | 两平台必做 |

主改进可选轻度运动模糊/亮度增强，与旧原型的明显退化问题对应。不要同时更换检测头、输入分辨率、采样方式和增强后将全部收益归因于其中一项。800/960 输入、RT-DETR、Faster R-CNN、SAHI 作为有时间才做的后续选项。现有 YOLO11 足以完成主问题，不必追逐新型号。

n/s 控制相同源域清单、预训练来源、输入尺寸、优化器策略、最大 epoch、patience、评估协议和可行的 batch。模型实际早停轮次可不同，但要报告；资源不允许同 batch 时，说明并考虑有效 batch/优化步数。每次运行使用唯一 experiment_id，保留 resolved args、训练曲线、日志、best/last、权重哈希和实际训练轮次，避免 `exist_ok=True` 覆盖证据。

## 检测与复核指标

| 指标 | 用于回答什么 | 注意点 |
| --- | --- | --- |
| mAP50 与 mAP50-95 | 整体检测与定位表现 | 标准 AP 评估保持低置信度候选，与部署阈值分开 |
| 四类 AP、目标数、图片数 | 是否只对某类有效 | 缺失类别记 N/A，不能错位按数组下标取类 |
| 固定阈值 Precision/Recall/F1 | 实际展示时会漏多少、误报多少 | 阈值在 val 选，test 不再优化 |
| D40 对象召回 | 坑洞对象是否被定位检出 | 一对一、同类别、GT IoU≥0.5，明确匹配算法 |
| 图像级 D40 检出率 | 含坑洞图片是否触发复核 | 与对象召回分开，不能混用 |
| 无目标图误报率 | 增加了多少人工复核工作 | 至少一误报图数/无目标类标注图数 |
| FP/图 或 FP/100 图 | 模型是否给人太多干扰 | 图像标注可能不完备，抽样人工复核 |
| 逐国结果与域外差值 | 迁移是否可靠 | 绝对差和相对下降都列，样本/类别构成不同 |

Ultralytics 当前文档说明汇总 P/R 使用 max-F1 工作点，可能不同于指定置信度的混淆矩阵；现有 CSV 的 D40 Recall 不能直接当作网页 `conf=0.25` 的召回。旧版本具体行为还要核对其实现。见[官方验证说明](https://docs.ultralytics.com/modes/val/)。

阈值选择建议：先在 val 记录默认阈值误报负担，预先规定可接受上限，再在上限内尽量提高 D40 Recall；冻结 class-specific 阈值和 NMS 配置后评估 test。若给 D40 低于其他类的阈值，模型输出的全局 conf 要足够低，不能先在 0.25 截掉候选再声称使用 0.15。

四类 AP 的读取按评估器的实际 class index 映射，不假设 `ap50[3]` 一定存在且代表 D40。某国类别少时给支持样本数。美国 D40 原始只有 135 框，召回变化需谨慎解释；有余力时按图像/采集组做 bootstrap 区间，不能把每个框当作完全独立样本。

## 泛化与鲁棒性

clean 与每种扰动使用完全相同的图片、标签与阈值；记录样例 ID、变换参数、随机种子。旧脚本使用 400 张、约 75% 任意对象阳性采样，其 clean mAP50=0.2978 不应与全量 test 的 0.2846 直接比较。新版本按目标四类重新标记并冻结子集；报告样本构成。

合成暗化、模糊、雾和噪声只是受控输入扰动，不等价于真实夜间/恶劣天气验证。先验证轻/中程度变化，避免只用极强噪声得到必然崩溃的结论。对每个条件报告相对同子集 clean 的退化，明确是否同时评测 n/s，不能把只测 s 写成两模型都验证。

失败案例先做 GT 与预测的同类别 IoU 匹配，导出 FP/FN 列表，再选择至少 3 例误检、3 例漏检解释。显示 GT 和预测不同颜色、阈值和样本 ID；人工判断与自动匹配分开记录。模型 AP 变高本身不能证明学到了某种因果特征。

## 运行性能

拆成模型推理边界与用户完整任务边界。前者若测 `predict` 就称预测调用耗时；仅测张量 forward 才称纯前向。后者覆盖读取/解码、预处理、推理、NMS、规则、叠框、编码/导出。网页响应另含排队与网络。

固定图片/真实短视频、batch=1、imgsz、精度和模型哈希。记录冷启动、warmup 数、样本数、mean/p50/p95、总帧数/总耗时、失败/丢帧与内存。CPU 用墙钟计时；CUDA/MPS 需要按后端正确同步，不能在 Mac 调 `torch.cuda.synchronize()`。

固定时长视频离线完成不等于实时。P95 低于 33ms 也不证明零丢帧；FPS≥30 只能支持对应设备与实测链路的结论。此项目先保证可交互演示，Mac 无需被强行定义为 30 FPS。
